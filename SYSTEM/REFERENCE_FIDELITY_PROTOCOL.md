# BA2-V1 — REFERENCE FIDELITY PROTOCOL

## PURPOSE

Preserve authoritative visual, textual, scene, character, location, and technical references with minimum unauthorized intervention.

## 1. REFERENCE AUTHORITY

A reference is authoritative only when the active project explicitly designates it as authoritative or the current user instruction makes it authoritative for the task.

## 2. LOCKED REFERENCE

If a reference is marked LOCKED:
- preserve its established content;
- do not redesign it;
- do not add unsupported elements;
- do not remove existing elements unless the user explicitly requests a controlled change.

## 3. CHANGE-ONLY RULE

When the user asks to modify an authoritative reference:
- identify exactly what must change;
- preserve everything else;
- do not invent additional architectural, character, wardrobe, lighting, camera, or environmental changes.

## 4. REFERENCE FIDELITY GATE

Before final output, check:

- correct project reference?
- current rather than superseded reference?
- all locked/reference elements preserved?
- only requested elements changed?
- no unsupported elements invented?
- no accidental carryover from another shot/project?
- requested output type preserved?

If any answer is NO, correct the output before finalizing.

## 5. SHOT RESET

For a new shot, do not carry forward previous-shot:
- camera;
- lens;
- framing;
- movement;
- focus;
- lighting;
- atmosphere;
- action;
- wardrobe;
- blocking;

unless the current authoritative reference or user instruction explicitly reactivates them.

## 6. REFERENCE REPLACEMENT

Replacing an authoritative reference is a controlled project change.

Use CHANGE_MANAGEMENT_PROTOCOL.md:
- classify scope;
- identify old/new reference;
- analyze dependencies;
- request approval when material;
- mark the old reference SUPERSEDED;
- activate the new reference only after approval.

## 7. MINIMUM INTERVENTION

The default editing principle is:

PRESERVE EVERYTHING → CHANGE ONLY WHAT WAS REQUESTED.
